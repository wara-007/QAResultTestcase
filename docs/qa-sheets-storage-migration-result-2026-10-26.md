# ผลการย้าย flow และลด Storage — 26 ตุลาคม 2026

## Flow ใหม่

- การนำเข้าจากลิงก์ Sheets/Drive เก็บ Excel ชั่วคราวในหน่วยความจำ ใช้แยกข้อมูลและรูป แล้วบันทึกเฉพาะ metadata/checkpoint ลง Supabase รูปยังอยู่ใน Drive ของผู้สร้างตาม flow เดิม
- ไม่ต้องเปิดแต่ละเคสเพื่อบันทึกรูปทั้งหมด
- ไฟล์ Excel ที่ผู้ใช้อัปโหลดเองยังเก็บต้นฉบับ เพราะไม่มีลิงก์ให้ดึงกลับ
- รองรับโปรเจคเก่า: source รุ่นเดิมยังอ่าน Storage ได้ การนำเข้าครั้งถัดไปใช้ flow ใหม่
- หน้าที่บันทึกผลครบแล้วอ่านรายละเอียดกับรูปจากข้อมูลที่บันทึกไว้ ไม่ต้องโหลด Excel ทั้งเล่ม
- การเปิดต้นฉบับหรือ Export จะดึง Sheets ตาม source revision ที่ถืออยู่ ถ้าเปลี่ยนแล้วต้องอัปเดตข้อมูลก่อน ไม่ใช้ตำแหน่งแถวเก่ากับไฟล์ใหม่
- Export ที่รักษาหน้าตาต้นฉบับยังต้องเข้าถึง Sheets ได้ ไม่ใช่เครื่องมือสร้าง Excel ใหม่จากฐานข้อมูลเพียงอย่างเดียว

## ทดสอบจริง

Pay ban cancel: source v10, metadata-only, byte_size=0, ไม่มี Storage key, complete=true, refreshRequired=false ชื่อเคสครบ42รายการ หลักฐาน239/239 แท็บ23/23 เปิดรายละเอียดและรูปจาก Drive ได้ หลัง reload หน้า Export endpoint ดึง source v10 จาก Sheets สำเร็จ HTTP200

ทดสอบอัตโนมัติ606รายการผ่าน, build ผ่าน, TypeScript/lint/read-only regression ผ่าน มี independent review และแก้ประเด็น local upload, hydration ตาม source ID, การอ้างอิงไฟล์ระหว่าง cleanup และการต่ออายุล็อกที่หมดอายุแล้ว

- ลบสำเนาเก่า131รุ่น รวม2,102,419,929ไบต์ (2.10GB) ตาม fingerprint ในเอกสารรายการอนุมัติ
- ไม่ลบ source metadata rows: เก็บ audit marker พร้อม original key และจำนวนไบต์ที่ลบ
- ไม่ลบเคส ผลทดสอบ Google Sheets หรือรูปใน Drive
- ขณะลบใช้ database write guard และปลดล็อกหลังเสร็จ ตรวจแล้ว active cleanup leases=0
- เคสในฐานข้อมูลยัง912แถว ผลทดสอบ912แถว

## พื้นที่ที่เหลือ

SQL ตรวจ storage.objects หลังลบพบ318objects รวม2,264,349,790ไบต์ (2.264GB) ยังเกิน Free1GB จึงยังสรุปว่าแก้ปัญหาโควตาครบแล้วไม่ได้

พื้นที่ที่ลงทะเบียนไว้ใน source_files เหลือประมาณ1.63GB ส่วนต่างประมาณ0.63GBต้องตรวจไฟล์จริงกับการอ้างอิงต่อ ไฟล์ที่ไม่ยืนยันว่ามาจาก Sheets และไฟล์ล่าสุดที่ระบบยังใช้ถูกเก็บไว้ ไม่มีการลบนอก131รุ่นที่อนุมัติ

Billing average เป็นตัวเลขย้อนหลัง จึงอาจยังไม่ลดทันทีตามพื้นที่ปัจจุบัน

ไฟล์ audit ราย object และ before/after metadata อยู่ในเครื่องที่ /tmp/qa-source-cleanup/ ไม่รวมใน Git ไม่มีการ commit หรือ deploy ในงานนี้
